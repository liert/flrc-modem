## 真实 IQ 端到端

输入：`pair_2480_10.iq`（外部 DK32S 对频录制 IQ 文件）。

- 输入格式：交错 signed-int8 I/Q。
- 采样率：10MSps；中心：2480MHz；目标：2480.060MHz。
- 输入 SHA-256：`DD2D68378E4FE390FB756BB03F5057A8FC8E36F4C30004DE6A0E4AEFC7D0C032`。
- 原始输入留在原位置，没有把 68MB IQ 复制到项目。

```powershell
python -m flrc_modem --iq capture.iq --config templates/dk32s_325k.toml --output outputs/dk32s.jsonl --quiet
```

结果：**18 帧 CRC24 成功**，35 个处理窗口，17 次重叠窗口重复命中被合并。候选组计数 36 包含重叠重复；没有把未通过 CRC 的噪声候选写成成功帧。

18 帧的完整 `payload_hex` 与旧 DK32S 脚本已验证记录逐帧完全一致。首帧约 1.54365ms：

```text
Sync     b4 2b 2b b4
Header   00 22
Payload  21 2a 72 04 00 98 f0 06 13 e4 0a 2b 3f c2 bf 8d 21 2d 4f 9c 81 02 e1 57 af 66 ce 3c 34 12 6e 90 e8 46
CRC24    ce 85 19
```

项目保留 Payload 的全部 34B，不剥离 DK32S 时间戳或解析命令号。生成结果位于 `outputs/dk32s.jsonl`，该目录由 Git 忽略。

## 同步字差分链修复

2026-10-19，用户提供可重放触发接收机响应的 `DK32S/rf/re.iq`，8MSps、重放中心 2473.200MHz。文件 147849216B、9.240576s，SHA-256 为 `836236947f75a78511c3a610b6c4b163eea90e762c600b32d164ae4a1944e4ef`。

在目标载频 2473.660MHz 解出 76 个 CRC 正确报文，地面/天空各 38 包，同步字 `d5e2870c`。原合成器与全部 76 包在零起算第 53 位（同步字首位）不一致；38 个强地面包的完整硬判决比特与原合成器仅此一位不同。

原因：原编码器对同步字和编码数据分别使用 0x66 相位重新起算。修正为同步字与编码数据拼接后，以 0x99 初相位执行连续差分映射。同步字最低位为 1 时，数据首位也必须继承同步字末态；另一份已有真实捕获的 `183a1d2f` 同步字同时验证了这一边界。

`tests/fixtures/air_bitstreams.json` 保存从真实 IQ 相位差直接提取、未经 FEC 纠正的两组比特：DK32S 499bit、已有 DataLink 捕获 264bit，修正后逐位完全一致。此前仅检查解码结果的回环会被接收器的 0x66/0x99 双候选及 FEC 掩盖，不能作为完整空口比特一致性的证据。

用户在修正后确认发送已可用；本轮未由助手另行执行真实射频发送，也未据此声称所有 CR/BT/速率档位均已完成硬件互通验证。

2026-10-19 多设备实测：枚举到两个索引，索引 0 序列号无法读取，自动打开时跳过此项，成功打开索引 1（序列号末尾 `2a5faf67`）并关闭句柄；按序列号后缀、按索引显式打开也均通过。只执行枚举、打开、读设备信息及关闭，没有启动射频收发；记录见 [设备选择测试](data/device-selection-hardware.json)。

## 不落盘实时发送

2026-10-19，真实 HackRF 以 2MSps、325kb/s、TEST 同步字发送自定义测试载荷。三帧有限发送、空闲 0.8 秒后动态追加报文、持续重复限时停止均通过，固件欠载为 0，停止后 `active_mode=0`。有限与动态发送的 USB 提交/完成字节相等，TX flush 成功。另验证 CLI 连续重复 2 秒自动停止。

初版两个块预填充不足以应对 libhackrf 启动时的四个连续取数回调；最终默认原始池 8 块、预填充 4 块，并补上对应回归。用法及缓冲延迟见 [实时发送](transmission.md)，统计见 [硬件数据](data/transmit-hardware.json)。测试未写出 IQ；发送数据通过模拟回调捕获后在内存中解调，空口接收互通尚待独立 SX1280 设备验证。

## 实时接收

默认当前 325kb/s 单信道选择 2MSps，采用独立 DSP 进程、100ms 步进与 6ms 重叠。真实设备连续 15 秒完成 3000 万复数采样接收，窗口队列最高 1，固件丢样为 0；计时取消持续会话后设备 `active_mode=0`，已收到字节全部交给消费者。详细参数与边界见 [实时解调说明](realtime.md)，统计见 [15 秒数据](data/live-hardware-2m-15s.json) 和 [取消测试](data/live-hardware-2m-cancel.json)。

初版 10MSps/50ms 及后续同进程 DSP 接收出现窗口积压；最终默认改用 2MSps 和独立进程。上述通过结果针对最终配置。本次现场实时测试没有 CRC 成功帧；成功帧验证来自软件波形回放及真实录制降采样回放。前端优化后，原 10MSps 全文件的 18 帧载荷、同步字及 CRC 逐帧保持一致。

## 调制回读

```powershell
python -m flrc_modem modulate --payload-hex 212a72040098f00613e40a2b3fc2bf8d212d4f9c8102e157af66ce3c34126e90e846 --sync b42b2bb4 --output outputs/modulated-dk32s.iq --repeat 3 --verify
```

结果：3/3 帧成功回读，同步字 `b42b2bb4`、硬件头 `0022`、完整 34B 载荷和 CRC `ce8519` 一致。使用默认 12µs RampTime 时，输出 448444 个复数采样，10MSps、cs8，时长 44.8444ms。参数同时保存在 `outputs/modulated-dk32s.iq.json`。

这是软件回环验证；SX1280 硬件空口互通尚未实测。
