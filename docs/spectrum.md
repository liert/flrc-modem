# SDR 实时频谱与瀑布图

WebUI 导航中的“SDR 实时频谱”支持 USRP、HackRF 和 IQ 文件回放，执行接收、频谱分析及可选的实时解调。接收时保留有界的原始 IQ 历史；只有录制或导出选区时才写入文件。

## 使用

1. 选择设备类型和物理设备；设备定位统一由设备选择器管理。
2. 设置中心频率、采样率、FFT 点数、窗函数及对应设备的接收参数。
3. 点击开始采集。后台收到首块 IQ 后才返回成功，USRP 图表使用实际回读的采样率和中心频率。
4. 暂停显示会保留接收与最新一帧，恢复时展示最新数据，暂停期间在瀑布图中留白。
5. 修改频率或增益后，点击“应用频率/增益（重启接收）”。后台先停止接收并释放句柄，再重新配置接收，期间会有采集间隙。更新使用所选 USRP 通道，零增益不会被默认值覆盖。
6. 设备、采样率、主时钟、FFT 点数、窗函数、天线或通道变化需要重新开始采集；界面会提示。USRP 主时钟与计划采样率联动，采样率被硬件对齐不会反复触发“需重启”提示。
7. 切换到其他工作台时继续采集，返回后保留参数、图表及解调历史。点击停止采集时释放设备，并保留最后的 IQ 缓存供选区导出；开始新采集后，旧会话的缓存失效。

显示参考电平默认为 0 dBFS，动态范围默认为 100 dB，对应 −100..0 dBFS 的频谱纵轴和瀑布色阶。可在“显示电平”中手动调整；采集启动和重新调谐时保持用户设置，不自动匹配电平。显示范围不修改 IQ、接收增益或绝对功率标定。频谱帧计数用于区分后台已有 FPS 与前端实际收到数据。

FFT 点数支持 256、512、1024、2048、4096、8192；刷新上限为 1..30 FPS。HackRF 采样率与增益范围由已有驱动配置类校验。无效参数在打开硬件前拒绝。

## 实时解调的物理模板

在“内置实时解调通道 → 物理层模板 · physical”选择现有模板，例如 `physical/dk32s.toml` 或 `physical/h12.toml`。界面显示码率、编码率、BT、硬件头、CRC 位宽和候选包长，可展开查看完整 `[demod]` 配置。模板元数据中的已知协议会填入应用层解析器，也可单独修改解析器。

采集前选择模板后随下次启动生效；采集期间点击“应用解调配置”可热切换，重新建立解调管道并清空跨配置的解调窗口，无需重启 SDR。开启解调、应用调节和选区解调均携带所选模板。物理模板中的 `[demod]` 参数完整传入解调器，包括滤波、同步字候选、硬件头、包长和 CRC 初值候选；实际采样率、采集中心频率、解调频点和 IQ 格式使用当前实时流参数。H12 1.3Mbps 需要至少 5.2MSps 的实际采样率，不能用模板标注的采样率替代硬件实际值。

后端在应用前验证模板及完整配置；失败时保留当前运行配置。清空模板可恢复原有默认配置。模板文件的修改在下一次应用配置时重新读取，运行中的解调不逐帧读取文件。

`POST /api/v1/spectrum/start` 和 `/api/v1/spectrum/update` 接受 `physical_template`（相对于 `templates/` 的名称）。更新中省略字段表示保留原值，显式 `null` 表示清空模板；`bit_rate`、`coding_rate`、`sync_word` 和 `crc_initial` 的显式覆盖优先于模板，传 `null` 恢复继承。状态响应中的 `demod_physical_template` 表示已应用的模板。

### DK32S 教练模式对频显示信号但没有解调包

教练对频使用 FLRC 325kbps、CR=3/4、BT=1、变长硬件头和 CRC24。选择 `physical/dk32s.toml`，解调中心设为 **2480.060MHz**；例如 HackRF 采集中心保持 2480.000MHz，解调框偏移设为 +60kHz。需要限定公共配对同步字时填写 `b42b2bb4`，CRC 初值填写 `FFFFFF`。模板中的采样率不会替换硬件实际采样率，HackRF 可先用 8MSps。

教练对频业务命令为 `0x5C/0x5B`，与普通配对的 `0x13` 不同，但物理层配置相同。业务解析器不认识某个命令，不会阻止 CRC 正确的物理帧显示。

侧栏“实时解调诊断”区分以下情况：

- 已处理窗口不增长：检查解调是否开启、是否仍在初始化，或是否出现明确错误。
- 窗口增长但候选为零：检查解调频点及信号质量；频谱中存在能量并不代表检测到了 FLRC 前导。
- 有候选但 CRC 通过为零：核对物理参数、同步字、CRC 配置及接收过载/信噪比。
- 丢块持续增加：实时处理未跟上输入；检查运行后端的同一个 Python 环境是否安装了 Numba。

从仓库根目录执行 `.venv/Scripts/python -m pip install -e .` 可补全声明的运行依赖，随后用 `.venv/Scripts/python -m flrc_modem webui` 启动后端。解调异常会显示具体原因并仅关闭解调，SDR 采集继续；修正配置后重新开启即可重建管道。

### 在频谱图中拖动解调框

频谱图默认显示半透明的“解调框”，中间虚线表示解调中心频率，左右边界表示所选模板的滤波通带（宽度为 `2 × filter_cutoff`）。左右拖动框体或顶部频率标签，标签随拖动显示频率；松手后更新侧栏频率，并向运行中的会话应用解调配置。拖动期间不逐帧请求后端，快速连续调整会合并并依次提交，仅保留最新待处理频点。

框的位置与图表频率缩放同步；拖动仅改变数字解调频点，完整通带限制在当前采集带宽内，不重调谐 SDR。“回中”将框放回采集频带中心并恢复全频段视图，“解调框：开 / 关”只控制框的显示。关闭实时解调时仍可定位框，开启解调后使用该频点。

聚焦解调框后，左右方向键微调 1kHz，Shift + 方向键调整 10kHz，Alt + 方向键调整 100Hz，Home / End 移至完整通带可容纳的采集频带边缘。拖动框与瀑布图的时空框选独立。

## 读数与时间

### 快速 IQ 录制的完成状态

只有 IQ 文件写入、刷新和关闭、伴随元数据写入，以及任务与产物登记均成功，录制才返回 `completed=true`。任务与产物在同一个数据库事务中登记，登记失败不会留下成功任务记录。

任一步骤失败时返回 `completed=false`、具体 `error` 和 `run_id=null`，保留已有 IQ 文件供恢复。界面展示失败原因，不显示完成卡片；手动停止、定时结束和停止采集使用相同的完成规则。

### 框选历史区域送入离线解调

1. 在瀑布图中框选一段时间和频段。拖动期间图表暂时冻结，后台接收继续；松手后选区随原始时段向下滚动，频率缩放也不会改变选中的信号。
2. 点击“送入解调”。后台从原始 IQ 历史中按采样点提取选中时段，写入 `outputs/captures/selection_<唯一标识>.cs8` 或 `.cf32`，并生成相邻的 `.json` 元数据文件。提取不重新接收信号，也不从 FFT 功率重建 IQ。
3. 文件完整写入后才进入命令页。草稿自动填写 IQ 路径、实际采样率、实际采集中心频率、选区目标频率、采样格式和当前物理模板/覆盖参数。文件保留完整采集频带，横向选区指定数字解调的目标频点；`--center-frequency` 与 `--frequency` 分别传递，频偏由离线解调器处理。
4. 运行离线解调，之后可以调整解调参数，重复使用同一个选区文件。

IQ 缓存最多保留 20 秒、256 MiB 和 8192 个块，按最先达到的限制淘汰最旧样本；内存按接收到的数据增长。瀑布图右上角的“IQ 可用”显示实际保留时长。例如 8 MSps 下，HackRF 的 CS8 最多约 16.8 秒，USRP 的 CF32 最多约 4.2 秒。暂停显示不会暂停接收和缓存淘汰；需要保留某段信号时应及时导出，或停止采集后再框选。

选区早于缓存、跨越接收缺口、包含丢样或混合采样率/采集中心频率时，导出会明确报错，保持当前页面和原有解调草稿，不输出伪造的连续 IQ。尚未完整采集的时段也不能导出。HackRF 的主机回调抖动按连续样本时钟处理，驱动报告的丢块仍视为缺口。File 输入的 CS8/CU8 在回放时已经归一化为 CF32，导出相应使用 CF32。

`POST /api/v1/spectrum/selection?session_id=...` 接受 `time_start`、`time_end`（墙钟秒）、`sample_rate`、`center_frequency` 和 `target_frequency`，响应包含文件路径、格式、实际样本边界和样本数。频谱帧及状态中的 `iq_history` 提供可用时间范围和容量。一次仅允许一个选区导出，写盘在工作线程执行，不持有接收缓存锁；失败会清理临时文件。`spectrum.selection_export` 日志包含请求/会话标识、结果、错误原因、导出字节和耗时。

“解调此频点”则开启实时解调，处理该频点后续接收到的数据，不回放历史选区。

### 频谱读数

频谱使用复数双边 FFT、fftshift 和窗函数相干增益归一化。定义为 `20*log10(abs(FFT)/sum(window))`，单位 dBFS；幅度为 1、恰好落在 FFT bin 上的复单音对应约 0 dBFS。非整 bin 单音存在窗函数相关的栅栏损失，三点插值仅作为峰值估计，不能保证任意频偏下幅度严格不变。频谱平均在线性功率域计算，随后转换为 dBFS。

这不是按 Hz 归一化的功率谱密度，也不是经过绝对功率标定的 dBm。`rbw_hz` 表示 FFT bin 间隔 `sample_rate/n_fft`，不等于所有窗函数的等效噪声带宽。

瀑布图使用固定 400 像素时间缓存、20 像素/秒的时间比例，显示约 20 秒。USRP 使用 UHD 样本时间映射到主机墙钟；HackRF 无同等硬件时间戳，此处明确显示为主机估计时间。丢帧、暂停和断流按时间间隔留白并标记，频率网格改变时标记分隔并重置峰值保持，跨采集参数的选区不能导出。画布缩小时按像素取最大值保留窄峰。

频谱缩放只影响图表，不调谐硬件；瀑布图保留完整采集频带。峰值读数为整个采集频带的峰值估计。

## 缓冲、通信与设备释放

- 原始 IQ 队列最多 8 块，积压时淘汰旧块并计数；DSP 累积样本数量有上限。
- HackRF 的设备打开、USB 接收回调和关闭放在独立子进程中，原始 IQ 通过 8 个 1MiB 共享内存槽位传递，管道只传递小型槽位描述，避免子进程崩溃后阻塞在半包 IQ 上。USB 缓冲池 32 块；主进程处理不及时会丢弃新块，并在后续数据标记间断、累计显示丢块计数。停止时先等待子进程退出，必要时终止该子进程，确认退出后释放设备占用。
- HackRF 原生驱动访问冲突会作为频谱采集错误返回页面，包含子进程退出码。服务生命周期日志统一保存在 `logs/webui.log`（单文件最大 10MiB，保留 5 份轮转备份）；服务原生堆栈为 `logs/crash.log`，接收子进程堆栈为 `logs/spectrum-hackrf-<pid>.fault.log`。`-1073741819 / 0xC0000005` 表示原生内存访问冲突，不能仅凭采样率判断具体故障模块。
- 仅通过 `/ws/spectrum?session_id=...` 推送频谱及状态，不推送全速 IQ。每个订阅队列最多 2 帧，DSP 到事件循环的待处理通知也有界。
- WebSocket 固定绑定会话，前端过滤旧会话与旧连接事件。接收数据或调整显示参数不会重建连接；短暂断线自动重连。
- 接收或 DSP 错误会传播到页面。接收线程退出并关闭硬件后才释放全局设备锁；停止超时时保留句柄和锁，避免另一个任务并发访问仍在运行的设备。
- 后台定期运行看门狗：无订阅者超过 15 秒，或仍有连接但超过 30 秒无心跳时停止会话。暂停状态也适用。服务退出时停止会话及看门狗。
- HackRF 连续接收显式禁用驱动默认的 30 秒总超时；连续 5 秒没有新 IQ 时报告接收中断并清理设备。

## 验证

```powershell
.venv/Scripts/python -m pytest tests/test_spectrum.py tests/test_spectrum_regressions.py tests/test_spectrum_file.py tests/test_spectrum_selection.py -q
cd webui/frontend
npm test
npm run build
```

测试覆盖单音频率与幅度、线性功率平均、实际 USRP/HackRF Python 封装配合模拟原生驱动、零增益、采样率回读、设备互斥、启动失败、停止超时、暂停恢复、看门狗、跨线程通知及 HTTP/WebSocket 数据流；前端覆盖会话过滤、重连、时间比例与窄峰保留。

这些测试不会连接真实硬件。实机连续运行、不同硬件型号的调谐及增益支持范围仍需接入相应设备验证。
